# 字符字幕与控制协议4

串口1152008N1，无流控。固定10字节：A5 5A CMD SEQ A0 A1 D0 D1 CRC_LO CRC_HI。
CRC16/CCITT-FALSE，初始FFFF、多项式1021，覆盖CMD至D1。
除逐字写入21外，等待匹配SEQ/CRC的应答。按键不自动重发。

| CMD | 功能 | 参数／应答 |
|---|---|---|
|01|状态|81：A0图片索引，A1数量，D0={state[2:0],volume[4:0]}，D1 flags|
|02|参数|82：A0亮度0..10，A1速度0..5，D0错误码，D1协议版本4|
|03|事务故障快照|83：32位小端原始快照，保留至下一次故障；跨故障首错码见07|
|04|实时事务|84：32位小端原始快照|
|05|HDMI进度|85：样本、非零样本、ACR、ASP的8位观察计数，异步采样不可作精确测量|
|06|加载耗时|86：最近加载的50MHz周期数，32位小端|
|07|恢复记录|87：32位小端，最高字节首错码，其次错误次数、恢复次数，最低字节为尝试次数／状态|
|08|调度记录|88：高16位音频扇区接受数，低16位图片扇区接受数，均饱和计数|
|09|字幕状态|89：低字节[7:6]显示源、[5:4]内置消息号、[3]普通覆盖有效、[2]紧急有效、[1]视频PLL锁定、[0]27MHz参考PLL锁定；次低字节剩余秒数；高16位最近缺字编码|
|10|单次按键|D0键号0..15，90返回结果|
|11|目标音量|D0=0..10，91返回结果；实际档位以01为准|
|12|私有音频诊断|原有模式0..7；默认6，测试音关闭，不在普通界面暴露|
|20|开始文字上传|D0/D1字符数1..64；A0=0普通、1紧急；紧急A1=1..120秒；A0返回结果|
|21|逐字写入|A0/A1为连续字符索引0..63，D0/D1为UTF-16 BMP编码，小端；无应答|
|22|提交|D0=1；完整长度和次序正确才合成，帧边界提交后A2应答|
|23|恢复内置中文|A3在内置文字重新提交后应答；同时清除普通覆盖并结束紧急|
|24|结束紧急|A4在恢复原普通字幕或内置中文后应答|

普通结果在应答D0：0成功，1参数非法，2忙，3上传不完整，4提交超时，5字库不支持。
01..09是原始快照，不将D0当结果码。
flags：bit0播放、bit1暂停、bit2媒体忙、bit3错误、bit4节目、bit5字幕实际可见、bit6紧急通知。
节目普通播放/暂停细分状态仍以屏幕节目状态为准，媒体FSM状态用于事务诊断。

上传空闲超时5秒，部分文字不提交；提交等待超时1秒回复4并释放协议等待。
超时表示未确认显示，不保证尚未发生提交。只有开始上传的忙响应允许软件有限重试，
按键、提交和紧急指令不自动重复。取消／到期保留原手动暂停状态。

串口不再提供任何字模、图案或像素上传入口。固定字库与位流一起生成，不能通过21修改。
双缓冲只在完整合成后于帧边界交换；不完整／缺字的后台结果不影响当前前台画面。

R290视频标准720p60、N6144/CTS74250；09最低两位由保留位改为实际视频双PLL同步锁定状态，正常应为3。
05计数为8bit回绕异步观察值，只能检查数据进度；它不能证明HDMI接收端已实际发声。

R298 音频模式：0F 查询，8F 应答 A0=模式（0统一、1逐视频），A1=0，D0=0，D1=A3（能力标识）。13 设置，D0/D1=0或1，93 应答D0=结果；非法值返回1且不改变模式，CRC错误不生效。复位默认统一。
普通轮播：统一模式始终选扫描顺序中的 WAV0，换图不重启，音轨结束后循环；逐视频按 BMP N 对应 WAV N，缺少对应 WAV 时静音，不回退到 WAV0。FAT目录扫描顺序不保证按文件名排序，应按该顺序准备素材。节目模式沿用已编排 WAV0 时间轴，此设置用于普通轮播，不重写节目时间轴。
